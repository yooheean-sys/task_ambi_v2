## 2. 根拠

- **D02-a**: C4 L1 は到達点の絵であり、マイルストーンの切り方とは独立。M1 のみで描くと casbin／AI 制御／Obsidian が外部要素扱いになり、後で境界を引き直すことになる。§6-3(7) の見出し「並列実行対応」と本文「Redis 等のブローカ＋ワーカー分離」が示す実質は並列化であり、トリガー自体は「2. やりたいこと」L32-35 と §6-1 M2 の両方でスコープ内と明記されている
- **D02-b**: beads-ui を beads に畳むと、E1 で実測した「人→beads-ui→beads←システム」の回答動線が見えなくなる。LLM を 2 箱にすると L1 の粒度を超える（同じ OpenAI 互換 I/F）。GitLab は「2. やりたいこと」L40 の語調（「さらに…したい」）が希望であり §6-3 にも未記載のため、境界を引かず次 ver 候補とする
- **D02-c**: constitution §0 が単一ユーザを前提。AI 役割をアクターにするとコンテキスト図（システム内部）と整合しない。無人起動は「誰が起動するか」を表すためタイマ／ファイル投下を副アクターに置く
- **D02-d/e/f**: 成果物リストにない「UC 記述」を csv で置くことで、フェーズ2 のシーケンス図・機能一覧が参照する正規テキストを確保する。CRUD 系の直線フローは図化しても情報量がない
- **D02-g**: mermaid にユースケース図の専用構文が無いことを docs で確認。C4Context は experimental だが mermaid-cli で描画成功
- **D02-h**: 今回のリンク変換で空白入り日本語ファイル名が CommonMark を壊すことを経験したため、新規ファイルは ASCII 名にする
- **D02-i**: §0-5 を厳格適用するとフェーズ3〜4 を「非コンテナ・DB なし」の大前提を知らずに進めることになり手戻りリスク。§5 は「人間の理解用」であり設計入力として読む方が §0-5 の趣旨（開発時の規約を設計に持ち込まない）と両立する
- **D02-j**: 6 フェーズ工程と §6-1 の議題は競合しない。議題は工程の中で当たる場所で裁定すればよい

## 3. 棄却した選択肢

| 選択肢 | 棄却理由 |
|---|---|
| コンテキスト図を M1＋M2 のみ／M1 のみで描く | 到達点との乖離。境界の引き直しが確定的 |
| AI 役割をアクターにする | 内外の境界が曖昧になりコンテキスト図と矛盾 |
| 人間を「運営者／管理者」の 2 アクターに分ける | 単一ユーザ前提との整合注記が要り、得るものが少ない |
| 全 UC をアクティビティ図化 | CRUD 系は保守コストだけが残る |
| コンテキスト図も flowchart | C4 の要素種別を色と形で代用することになる。描画は確認できたので C4Context を採る |
| 設計図を `outcome/` 直下に日本語名で置く | 6 フェーズで 20 ファイル超がフラットに並ぶ |

## 追記（2026-08-18）: 本文の行番号ポインタの現在値

本文は**一切変更していない**（append-only）。本文が使っている「§n Lnn」形式の行番号参照は、参照先が改訂可文書のため既に失効しうる。§0-2 の改訂により、改訂可文書は **ID で引く**規約になったので、現在値を対応表で示す。

| 本文の記述 | 現在の指し先 |
|---|---|
| §2 根拠「「2. やりたいこと」L32-35」（D02-a） | **§2 R-12**「トリガー実行への対応」 |
| §2 根拠「「2. やりたいこと」L40」（D02-b） | **§2 R-13-c**「さらに、設定でプロジェクトごとにgitlabのpathを登録…」 |
| §4「付録：トリガー §6 L54-56」 | **付録：トリガー実行機能の設計 §6「無人ガード」**（節参照で足りるため行番号は不要） |
