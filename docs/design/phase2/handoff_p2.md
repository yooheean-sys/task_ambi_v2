## 4. 第3フェーズ（Boundary Context 図）への入力と論点

工程文書: INPUT＝コンテキスト図（`../phase1/01_context.mmd`）・ドメインモデル・シーケンス図。OUTPUT＝★Boundary Context 図（mermaid）。完了条件は着手時に D 記録で定める（`00_conventions.md` 不在、D05-c と同型）。

論点（作業メモ A-0 に登録済み）:
1. **集約境界を Bounded Context の出発点にする**（notes.md §0）。実体（beads／vault／設定ファイル／インメモリ）の違いが境界と一致するように引いた。集約が別モジュールに割れないことを目標にする
2. **X2**: 実行コンテキスト（DM-19）を持ち運ぶモジュール。回復層・分解層の帰属（D01 §6-2）
3. **実物照合ゲート**の要否（§6-1 M1 議題の最後の 1 件。D01 と同じ P4 系列）
4. 設定ファイル群（DM-01〜07／11／12／22／26）の所有モジュールと、コマンド定義を AI 到達不能に置く構造（D07-e）
5. 各外部ストアの**所有モジュールを 1 つ**（憲章 §2）
6. §6-1 の**未配置**（`p2_feature_list.csv` 優先度=未配置: casbin・AI 制御・Obsidian 拡張・起票フォーム・台帳 等）の M3 以降への配置（§6-1 改訂。並行可）
