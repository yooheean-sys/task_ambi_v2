## 2. 根拠

- **D05-a**: フェーズ定義がリポジトリ内に無く（D02 は「ユーザ提示」と書くのみ）、作業メモ A-0 の 3 語だけが手がかりだった。工程文書の実体は 作者の個人 vault に存在し、第2フェーズの OUTPUT 仕様（classDiagram・DM-*・レーン規約・csv 列・実体の所在の注記）を明記している。コピーを置くと乖離するので所在を記録する
- **D05-b**: 工程文書の仕様と D02-h（ASCII snake_case・`outcome/design/phase<n>/`）は両立する。Q1 で仮置きした `01_domain_model.mmd` 等の名前・列は工程文書発見時点で破棄した
- **D05-c**: 完了条件の参照先が不在のまま進めると「完了」が主観になる（P3）。(ii) は本メモ規約「未裁定は作業メモ、裁定は D 記録」の機械的な検査形
- **D05-d**: D02-e と同じ判断（CRUD 系の直線フローは図化しても情報量がない）。UC-08・UC-07 は「ドメイン概念間の整合（存在検証・削除ガード・validate）」を見せる代表として採る
- **D05-e**: 高／中／低は根拠が主観になる。マイルストーンなら §6-1 と突き合わせて検証でき、未配置の量が §6-1 改訂の必要量を示す。kind 列は 05 §3 の引き継ぎ（P1 の三段を列で持ちプロンプト依存を可視化）
- **D05-f/g**: P4（一つの事実は一つの出所から）。CLAUDE.md は §0-2 ポインタ規約の改訂が未反映で既に乖離していた
