## 2. 根拠

- **D08-a**: notes §0 の集約境界を出発点にし（handoff_p2 §4-1）、憲章 §2「外部ストア（領域）ごとに所有モジュール 1 つ」を検査基準にすると、beads／vault／設定ファイル／csv／DL フォルダの所有が 6 BC に一意に落ちる。BC-05 を分けるのは、失敗検出が「戻り値以外の観測点」（付録 AI 制御 §3.2(a)、3-4 X-3）という独立した関心で、BC-03 の kickoff から見ると横断的だから。BC-03 を割らないのは、割る線（外側ループ／CrewAI 実行器）がドメインではなく実装の層だから（実行器はアダプタ）。行数の問題は MOD の問題であり BC の問題ではない
- **D08-b**: BC-03 → BC-01（kickoff 時に設定を読む）は必須。BC-01 → BC-03 も張ると双方向依存になり憲章 §3 補足に抵触する。列挙型は憲章 §7-5 の「型定義」に収まり、プロンプトは common に漏れない。min_items をモジュール config.json に置くのは憲章 §5「各モジュール config.json＝そのモジュール固有の非機密パラメータ」そのもの
- **D08-c**: 主体 `member:<project_key>.<persona_key>` はプロジェクト×メンバから導出され（D06-b）、validate 順方向・逆方向・cmd 突合（FN-16/17/54）は台帳・policy・コマンド定義を同時に見る。割ると validate が BC 横断になる。UC-07 は 1 つの設定 UI（垂直スライス）。DM-26 は「設定モジュールのみ所有」（D07-e）がそのまま成立
- **D08-d**: 生成者は起動元ごとに異なる（human 起動はトリガーを通らない）が、保持して貫通させるのは外側ループだけ。contextvar は憲章 §6 の correlation ID ミドルウェアと同型で、引数貫通より Protocol が細らない。snapshot を値コピーにするのは削除後も追える要件（D06-j(2)）を参照では満たせないため
- **D08-e**: 回復層を BC-02 に置くと盤面アダプタが `state:working` の意味論と再投入方針を持ち、beads 乗り換え時にロジックが道連れになる（憲章 §2 アダプタ分離の趣旨に反する）。BC-06 に置くと human 起動（CLI）で回復が走らない
- **D08-f**: (1) 🔒「内容評価不実施は裁定であり漏れではない」（§1）と §6-3 に触れる——「成果物中の識別子 ⊆ 入力中の識別子」は何を識別子とみなすかが成果物の種類に依存し、汎用に機械化できる形が無い (2) 実害は V3（deepseek）1 件で V3b（qwen）では再現していない (3) 帰属は要否によらず同じなので境界設計は止まらない
- **D08-g**: M の順序は入口条件＝先行モジュールの完了で決まり、それはフェーズ4 の Protocol 依存が出て初めて根拠を持つ。今決めるとフェーズ4 で再改訂になる
- **D08-h**: D05-c と同じ趣旨（完了を主観にしない）。(ii)〜(iv) が工程文書「1 つの DM が複数 BC に現れる場合は所有者を決める」「分割基準を BC ごとに一行」の機械検査形

## 3. 棄却した選択肢

| 選択肢 | 棄却理由 |
|---|---|
| 分解・遂行を「外側ループ＋ゲート」と「CrewAI 実行器」の 2 BC に割る（7 BC） | 割る線が実装層（アダプタ）でドメイン言語ではない。MOD 分割で足りる |
| 実行監視を BC-03 に畳む（5 BC） | 別のドメイン言語（等級・封筒）と別資産。kickoff から横断的で、畳むと BC-03 が更に肥大 |
| DM-08/09 を BC-01 所有にする | テンプレートの置き場が割れる（プロンプトは BC-03 の変更頻度で動く） |
| DM-08/09 は BC-03 所有のまま BC-01 が Protocol で引く | 双方向依存（憲章 §3 補足） |
| 権限（casbin: DM-04/26＋enforce）を別 BC に切り出す | validate の台帳突合が BC 横断になる。UC-07 の垂直スライスが割れる |
| DM-19 をトリガー BC 所有にする | human 起動も BC-06 を経由させる必要が出る |
| DM-19 を全 Protocol の引数で明示的に渡す | Protocol が細らない。憲章 §6 の correlation ID と二重になる |
| 回復層を BC-02／BC-06 に置く | D08-e 根拠のとおり |
| 実物照合ゲートを V4 で新設する | D08-f 根拠のとおり。帰属だけは記録した |
| 未配置 FN の M 配置を本フェーズで裁定する | フェーズ4 で再改訂になる |
| 成果物を mmd＋D08＋handoff の最小セットに絞る | 所有の一意性を機械検査できない |
