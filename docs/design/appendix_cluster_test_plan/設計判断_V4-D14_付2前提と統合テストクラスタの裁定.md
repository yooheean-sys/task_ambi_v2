## 2. 根拠

- **D14-a**: 付2 の出力は IF／EIF／UC の ID で引く表であり、付1 の裁定で変わり得るのは個別 IF の意味か EIF の Y/N 程度。実際に付1 は「設計を直す 0 件」で終わり、x2 の割当は不変。並行して進んだ 2 セッションが同じ D 番号を採ったのは採番の正本（索引）を着手時に読み直さなかったため（§4 に事実として記録）
- **D14-b**: 憲章 §8 が beads・vault・git の実物を要求し、CI に DB コンテナ不要と言い切っている以上、外部ツールを模擬する余地は LLM だけ。LLM はコスト・非決定性で assert が書けず、第5 の executor notes も「crewai のモックまたはローカル固定応答」と書いている。MockTransport を避けるのは monitor の `LLMHttpHook`（IF-40〜43）が httpx transport 層の差し込み点で、そこを飛ばすと C-B／C-D の主検証対象そのものが通らないため
- **D14-c**: orchestrator を 1 クラスタにすると 7 MOD（上限超）で、失敗箇所の切り分けが粗く LLM 偽サーバが周回テスト全部の前提になる。UC 境界で切ると C-C は executor／monitor をスタブにでき LLM 不要、C-D は実 executor＋LLM 偽で Hook→RunHalted→finish→写像の連鎖を実装同士で通せる。「主検証 1 クラスタ」にするのは被覆を機械検査するため（D09-h／D11-g と同型）
- **D14-d**: 「境界をまたぐ結合」の定義で最小完全。trigger は自分の router・scheduler・watcher・履歴 csv を持つので 2 MOD でも外部実体は最多（6）
- **D14-e**: 手配線（conftest が各 build を呼ぶ）だと apps/api の配線コードが検証されず憲章 §8 から外れる。全 8 MOD を常に実配線にすると C-C でも crewai の提案会話を LLM 偽に台本化することになり、クラスタを切る意味が薄れる
- **D14-f**: 工程文書の規則（外部依存が少ない順）を機械的に再現できる数え方にした。除外 3 件は全 MOD 共通で差を作らない。ダブル数を tie-break にしたのは「模擬が少ないほど実物に近い」から
- **D14-g**: D05-c／D08-h／D09-h／D10-g／D11-g／D12-g と同型（完了を主観にしない）。§6「検証観点」を足したのは、p5 の alt 分岐（BoardWriteUnverified・MappingUnverified・RunHalted・tool_denied 等）をどのクラスタが見るかが工程文書の 5 項目だけでは落ちるため
- **D14-h**: 置き場は apps/api が composition root（憲章 §3・§8）で、apps→features→common の一方向（§7-5）を保つ唯一の場所。REV-08 は「置き場は apps/api/tests（または repo 直下 tests/integration）」と両論を残し付2 の確定を待っていた。LLM の 1 行は、憲章 §8 が外部ツールを「実物」と言い切っている中で LLM だけ例外になる規則なので、書かないと AI が §8 を読んで LLM も実物で呼ぶテストを書き得る（誤読防止＝付1 で憲章を直す側に倒した 3 件と同じ理由）
