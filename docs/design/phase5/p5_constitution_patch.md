## PATCH-6 §2 アーキテクチャ原則 — 永続ストアの例外 (b) ローカルログ（P5D-044 / P5D-043）

**前**（§2 の例外列挙の 2 点目。PATCH-2＝DEC-003 で追加された文）:

> - **追記のみのローカルログ**: 実行履歴等の csv。システムのロジックは読み戻さず、表示にのみ読む（§4「ローカルの作業ファイル・ログはファイルシステム直置き」のログ扱い）。

**後**:

> - **システム所有のローカルログ**: 実行履歴等の csv。原則は追記のみだが、1 実行の開始時に書いた行を終了時に確定値で埋める書換えは許す（同じ所有モジュールが、自分の書いた行に限って行う）。システムのロジック（判定・分岐）はこのログを読み戻さず、表示にのみ読む（§4「ローカルの作業ファイル・ログはファイルシステム直置き」のログ扱い）。

**理由**: 第5フェーズの trigger 詳細設計（P5D-043）で、実行履歴を「開始時に行を書き、終了時に同じ行を全列埋めて書き換える」上書き方式と裁定した（ユーザ選択。kickoff 中にプロセスが死ねば `status=started` の行が残り未終了と分かる）。DEC-003 の趣旨は「システム固有の DB を作らない」「ログを判断材料に読み戻さない」であり、自分が書いた行の確定は趣旨に反しないが、字面の「追記のみ」からは外れるため文言を緩める。書換えの範囲を「同じ所有モジュール・自分の書いた行」に限定することで、ログが状態ストア（DB）に化ける経路は塞いだまま。

**影響**: 設計側の変更なし（trigger の成果物は上書き方式で記述済み）。`p45_constitution_diff.csv` DIFF-03／`decision_log.csv` DEC-003 は「例外列挙を設ける」裁定として有効、文言だけ本 PATCH で更新。付1 の適合チェックでは本 PATCH 適用後の文言で判定する。
