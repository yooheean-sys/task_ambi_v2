## 2. 根拠

- **D15-a**: 憲章 §2 例外 (a) が「宣言的設定ファイルは config.json と別系統・commit しない」と既に言い切っており（DEC-003）、領域 A を git 管理下にすると REV-07 の「UI からのみ編集」と両立しない。工程文書の (c) は汎用テンプレートの文言で、本プロジェクト固有の憲章が勝つ（§0-1 の優先規則）
- **D15-b**: 重複を許すと「.env に挙動設定が漏れ込む」余地が残り、憲章 §5「.env は秘密と環境依存値のみ」「config.json のパスは規約」を運用規約だけで守ることになる。機構（env ソースなし）で守れば AI 実装者も誤らない。テストの差し替えは D14-e が既に build() 引数の型を要求している
- **D15-c**: 憲章 §5 が `.env` を pydantic-settings の 1 ファイルと定めており、(b) を別ファイルに分けると「config のパスを .env に持たせない」と同種の規約が 1 つ増える。環境情報ファイルは憲章 §4 でも「手順・環境事実」の文書
- **D15-d**: beads_dir は絶対パス、bd_bin は systemd 下で PATH 解決できない環境がある＝どちらも環境依存値（憲章 §7-4）。commit ファイルに環境の値を置くと別環境で config.json を書き換えて commit することになる
- **D15-e**: 決定例「DL フォルダは (b)」をそのまま満たし、P5D-009（vault ルートは .env・領域は相対）と同型。領域 B が環境ローカルとはいえ絶対パスを残すと「ハードコードしない」の趣旨から外れる。監視対象は要求上 DL フォルダのみ
- **D15-f**: ui は憲章 §2「自モジュールを HTTP API 経由で操作」の器で、領域 A／MOD config を直接読む理由がない。有効 MOD 一覧だけはページの表示選別に要るためルート config.json を読む。Streamlit のポートは `streamlit run` の引数か `STREAMLIT_SERVER_PORT` でしか渡せず、app のように自分で bind できない
- **D15-g**: サービス種別を接頭にすると validate・UI 既定・マスクパターンが 1 つの規約で揃う。憲章 C-5-09 の `<MOD>_` 接頭は「MOD 固有の秘密」用で、LLM キーは外部サービスのトークン（§5 の第一の用途）
- **D15-h**: 読み手のない設定を V4 に入れると、項目・UI・validate・data_model が増えるだけで検証できない。D02-b は「希望であり §6-3 未記載」で次 ver としており覆す事実が出ていない。置き場を決めておけば次 ver で迷わない
- **D15-i**: 実値の読取点が 1 つ（P5D-030）なので、越境しない構造＋出口（ログ・例外・UI）のマスク＋入口（設定ファイル）の禁止＋走査テストで閉じる。gitleaks は有効だが憲章 §4 の CI 構成を増やし、単一利用者・`.env` 1 ファイルの規模では pytest 走査で足りる
- **D15-j**: CrewAI v1.15 の事実（§4）: classic の `agents.yaml` は `llm:`／`tools:` を**クラス内メソッド名**で解決し、`process_config` は宣言フィールドのみコピー・未知キー無視。@CrewBase は静的クラス前提で、本設計の issue・段ごとの動的 Crew・GuardedTool（casbin フェイルクローズ P5D-032）・不変スナップショット（P5D-016）とは別物。PoC も同じ理由で `Agent(...)` 直組み（casbin PoC README 15）。**ファイルの名前・フィールドを CrewAI に合わせ、ローダは自前**にすれば、ユーザ要求（標準ファイルで定義・UI で編集）と設計の制約が両立し、将来 @CrewBase／JSONC へ機械変換できる（casbin PoC の tasks.yaml 注記と同じ考え）。`tools.yaml` は CrewAI 標準に無く（Tool は Python・YAML からは名前参照のみ）、独自カタログを置くと tools.yaml＝存在／agents.yaml＝装備／policy.csv＝許可の 3 層になる。ユーザは「置かない」を選択（Q10-2）
- **D15-k**: D05-c／D08-h／D09-h／D10-g／D11-g／D12-g／D14-g と同型。c2 をファイル粒度にしたのはフィールドは p5 data_model が正本で、P5-R1 で書き直す対象だから
- **D15-l**: D15-b の「重複なし」から機械的に決まる。偽 LLM の base_url はプロファイル属性（DEC-006）なので .env でなく領域 A
- **D15-m**: 憲章 §5 のルート config.json 最低限＋D15-i の redact_keys。テレメトリ無効化は PoC 2 本が env で行っていたが秘密でも環境依存でもないので c1 から setdefault
